# T-0104 — UI Toolkit base style, HUD and input map

**Lane:** WORKER-3 (People & Interface)
**Depends on:** T-0001 (done)

## Goal

The interface foundation: a parchment-and-wood bordered style with a real pixel
font, a working HUD, and the Input System action map everything else binds to.

## Do

1. **Style**: a parchment/wood-bordered UI Toolkit theme — UXML and USS as text
   files, never a hand-composed Canvas hierarchy.
2. **Font**: a real pixel font, open-licensed (SIL OFL or CC0) so the WebGL build
   can embed it. Log it in `docs/ASSET_LICENSES.md`.
3. **HUD**: clock and date, season and weather, energy and health bars, money, and
   the hotbar row. Values read from `GameState` and refreshed on
   `state:changed` / the relevant bus events — never polled in `Update`.
4. **Input System action map**: move, look, interact, cancel, hotbar slots,
   inventory, pause. Must be usable by the Input System package, not the legacy
   Input Manager, and remappable later (options screen is M7, but the asset must
   not block it).
5. EditMode or PlayMode tests asserting the HUD reflects a known `GameState` and
   updates when the state changes on the bus.

## Do not

- Use Canvas or uGUI.
- Compose UI hierarchies in code where UXML expresses it.
- Poll state every frame.
- Commit.

## Accept when

- UXML and USS files exist as text under `Assets/UI/` and `Assets/Scripts/Features/*/UI/`.
- The HUD renders correct values for a constructed `GameState` and updates on a
  bus event, verified by a test with real assertions.
- The action map asset exists and is wired to the Input System.
- `scripts/run-tests.ps1` green in both tiers, with real counts.
- The report states the `-executeMethod` invocation for anything built by script.
