## Goal
A playable engine shell: a Three.js renderer that draws the farm map, the
player, and an interaction-highlight tile; an angled top-down follow camera;
simple key/mouse-driven movement that communicates with the sim via
store.dispatch, and reads everything else from store.state. No stubs, no TODOs.

## Files to create (all in YOUR lanes)
- src/features/engine/index.ts — registers your modules.
- src/features/engine/sim/PlayerPosition.ts — a small sim module
  (lane 'sim', id 'engine:sim') that registers reducers:
  - `player:move` ({dx,dy}): compute target = player.position + (dx,dy); it is
    walkable iff legend[code].walkable && not blocked by placed (see contract
    section 2). Update position+facing; tiny energy drain (0.02/tile); emit
    `player:moved` {from,to,mapId}. Reject diagonals (move primary axis only).
  - `player:interact`: reads selected inventory slot; does NOTHING except emit
    `tool:use-requested` {tile, toolId} on the bus — the farming sim (WORKER-2)
    owns tool outcomes; it listens for that event. Keep this reducer minimal
    (walk + facing + emission only).
  Collision data source: `ctx.content.maps.get(mapId)` for legend.
- src/features/engine/view/EngineView.ts — the renderer. Export
  `defineFeature({id:'engine:view', lane:'world', view(){ return handle }})`.
  It must:
  - Build a WebGLRenderer on `document.getElementById('game-root')`, resize
    handling, alpha background. Guard all DOM/three access behind a `headless`
    flag so importing the file in node never touches the DOM.
  - Procedural low-poly map tiles behind an ASSET-ID layer: a registry mapping
    legend codes and placed-object ids to "assets"; build placeholder-clean
    stylized meshes NOW (grass = green ground tile, soil tilled strips,
    water = blue plane, house = box, trees, rocks, weeds, shipping bin) —
    these are the cosmetics, not grey boxes; they must look intentional and
    cohesive (see ASSET_LICENSES for palette/CC0 orientations). Keep per-asset
    builders in their own files if handy (src/features/engine/view/assets.ts).
  - Read state.maps.farm: instantiate meshes from grid.tiles + placed objects.
    Rebuild incrementally: on 'state:changed' re-sync placed objects (diff by
    key), do NOT rebuild the whole map per frame.
  - Player mesh follows player.position with smooth lerp between tiles; face
    direction from facing. Simple low-poly humanoid (capsule/box limbs).
  - Camera: angled top-down (pitch ~55-60deg), position lerps to follow player,
    zoom wheel support, min/max clamp.
  - Interaction highlight: tile in front of the player (facing) is drawn with a
    translucent highlight quad; update each frame from sim state.
  - Lighting: ambient + directional with soft shadow map; a light color ramp
    driven by world.clock (day = warm, night = cool/dim) — cheap and good.
  - Expose a `render(dt, t)` on the handle; main loop is owned by your module's
    `view()` handle wired in main.ts (see below) — but first check whether
    main.ts already drives frames; if it does, hook into it via events instead.
    Decide ONE approach and document in report.
- main.ts — you MAY edit src/main.ts (it is a bootstrap file, core-owned).
  If you must change it, keep it minimal and note it in the report; default to
  calling `createGameRuntime({ mountDom:false })`..., then mounting your view,
  then a rAF loop calling handle.render(dt,t) and runtime.tickSimStep() every
  SIM_TICK_MS (7s the first milestone, keep it a const) plus moving every frame
  via dispatch. Prefer to make main.ts generic: iterate runtime.features and
  call .view() — do not hardcode.

## Keyed sim facts
- Player starts at state.player.position {mapId:'farm',x:4,y:6}.
- Farm map 32x24; legend codes g(grass,tillable), s(soil,tillable), w(water),
